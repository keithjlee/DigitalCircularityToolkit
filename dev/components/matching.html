Matching

Assign supply to demand at minimum total cost and place the matched objects. See Matching.

AlignToObject

Align an object to another

Nickname: AlignObj

Moves SourceObject onto TargetObject by matching their local frames. Each design object has a LocalPlane: X along PCA1, Y along PCA2, Z along PCA3, with its origin at the center of the object's oriented bounding box. The component builds the plane-to-plane transform from the source's frame to the target's frame and applies it to the source. After alignment the two bounding-box centers coincide and the source's PCA1 (length), PCA2 and PCA3 axes lie along the target's.

The move is rigid (rotation plus translation); nothing is scaled. A supply object that is longer than its target therefore overhangs it by the same amount at both ends. The aligned object keeps its concrete type (a LinearObject stays a LinearObject, with its quantity and buffers), and its analysis is moved with it rather than recomputed, so Length, Width and Height do not change. The input object is not modified; a copy is returned.

Use it after Match to place each assigned supply object at the position of its demand object: pick the supply objects with List Item using the Assignment indices (from the Objects output of the Set component, so the indices line up) and connect the demand objects as TargetObject. Geometry gives the moved geometry for display or baking.

Notes

  • Both inputs must be DCT design objects, for example from LinearObject, BoxObject or a Set component.
  • The component does not handle unassigned demand. Remove entries with Assignment -1 first: List Item with Wrap on turns -1 into the last supply item.
  • Transform is the transform that was applied; use it to move related geometry the same way.
  • The sign of each PCA axis comes from the object analysis, so a source can land flipped end to end relative to its target. Use RotatePCA to turn it, or OverridePCA to set the axes of the source before alignment.

Match

Perform linear assignment of supply to demand using the Jonker-Volgenant algorithm

Nickname: Match

Solves the linear assignment problem: it pairs demand items with supply items so that the sum of the costs of all pairs is as small as possible. The solver is LAPJV (Jonker-Volgenant, via the LapjvCSharp library), which finds the exact optimum.

DistanceMatrix is a tree with one branch per demand item and, in every branch, one cost per supply item: item j of branch i is the cost of assigning supply j to demand i. This is the output of EuclideanDistance, AsymmEuclideanDistance and ManhattanDistance. Branches are read in order; their path names do not matter. Assignment has one entry per demand item: A[i] = j means supply j goes to demand i. Cost is the sum of the costs of the assigned pairs.

Each supply item is used at most once. An inventory item with a quantity greater than one must therefore appear once per piece; the Set components (LinearSet, PlanarSet, BoxSet, SphereSet) expand objects by quantity, and their Indexer output maps a supply index back to the original object. With more supply than demand, the unused supply items do not appear in Assignment. With more demand than supply, the solver chooses which demand items stay unassigned so that the cost of the assigned pairs is minimal; those items get -1, and Cost leaves them out.

Downstream, use Assignment with List Item on the supply list (objects, centroids, geometry), draw the pairs with MatchLines, and place supply objects with AlignToObject.

Notes

  • AutoRun (default true) solves on every change. When it is false, the component keeps outputting the last computed result without re-solving, even if DistanceMatrix has changed; set it to true, for example with a button, to re-solve. The stored result is not saved with the file, so after reopening a file with AutoRun false there is no output until it runs once (remark: "AutoRun is false and no assignment has been computed yet. Set AutoRun to true (e.g. press the button) to run.").
  • Remarks when demand exceeds supply: "|demand| > |supply|, not all demands will be assigned a real supply item" and "N demand item(s) have no supply item: their Assignment is -1, and Cost excludes them". Check for -1 before indexing: Grasshopper's List Item with Wrap on turns -1 into the last item.
  • Errors: "DistanceMatrix is empty"; a branch with a different number of items than branch 0; a branch containing a null cost.
  • Cost is the sum of the integer costs in DistanceMatrix, so it carries the rounding and scaling of the distance component that produced them.

MatchLines

Get the lines that connect supply-demand assignments

Nickname: MatchLines

Draws a line from each demand point to the supply point it was assigned. For each position i in AssignmentIndices, the line runs from DemandPoints[i] to SupplyPoints[A[i]]. The output list has one entry per demand point, in the same order, so it stays parallel to the demand list.

Connect AssignmentIndices to the Assignment output of Match. The points are usually object centroids: for demand, the centroids of the design elements; for supply, the Centroids output of a Set component (LinearSet, PlanarSet, BoxSet, SphereSet). SupplyPoints must be in the same order as the supply columns of the cost matrix, which means the expanded list from the Set component, not the original objects. The lines are a visual check of the matching, for example to see whether items come from a nearby part of the stock.

Notes

  • Unassigned demand (index -1, when there is more demand than supply) gives a null entry at that position, with the remark "N demand point(s) are unassigned (index -1); their lines are null".
  • Error if DemandPoints and AssignmentIndices have different lengths, or if an index other than -1 is outside the range of SupplyPoints; no lines are output in either case.
