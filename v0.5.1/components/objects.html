Objects

Turn geometry into design objects: an abstraction (line, plane, box or sphere) in a local frame found by PCA. See Design objects and Orientation.

BoxObject

A volumetric box object

Nickname: BoxObj

BoxObject abstracts a piece of geometry as an oriented box. It runs the same sampling and PCA analysis as Object (see that note for how NumSamples, the PCA frame and Length/Width/Height are defined) and then stores Quantity, the three buffers and ID.

Effective box. The starting box is the bounding box of the full geometry aligned with PCA1, PCA2 and PCA3. EffectiveBox is that box scaled about its center by LengthBuffer along PCA1, WidthBuffer along PCA2 and HeightBuffer along PCA3, so

\[L_\text{eff} = f_L \cdot \text{Length}, \quad W_\text{eff} = f_W \cdot \text{Width}, \quad H_\text{eff} = f_H \cdot \text{Height}\]

A buffer below 1 shrinks the box (for example to keep only usable material); above 1 enlarges it (for example to add clearance).

Workflow. Use it for blocks, timber offcuts, stones and other volumetric elements that are not dominated by one or two dimensions. Collect supply and demand objects with BoxSet, which expands them by Quantity and outputs the effective boxes and dimensions for FeatureVector. BoxScore measures how well the box represents the object.

Notes

  • Error: "Buffer must be > 0" when any buffer ≤ 0, plus the geometry errors listed under Object.
  • The box bounds the whole geometry, so a single protrusion enlarges it.
  • Quantity 0 makes the object contribute no rows to BoxSet; a negative Quantity, or NumSamples < 1 for a curve or Brep, is an error.
  • The effective box is derived from the current axes, so it follows changes made with OverridePCA.

LinearObject

A linear object

Nickname: LineObj

LinearObject abstracts a piece of geometry as a line with a cross-section area. It runs the same sampling and PCA analysis as Object (see that note for how NumSamples, the PCA frame and Length are defined) and then stores Quantity, LengthBuffer, Area and ID.

Effective line. The EffectiveLine lies along PCA1, centered on the center of the object's PCA-aligned bounding box, with length

\[L_\text{eff} = \text{LengthBuffer} \times \text{Length}\]

where Length is the extent of the geometry along PCA1. A LengthBuffer below 1 shortens the line (for example to allow for trimming damaged ends); above 1 lengthens it.

Area. If Area is greater than 0 it is stored as given. Otherwise it is estimated once, at construction, as Width × Height: the rectangular cross-section of the bounding box measured along PCA2 and PCA3. This is a bounding rectangle, not the true section area, and it is not affected by LengthBuffer.

Workflow. Use it for bars, beams, studs and other members whose length dominates, on both the supply side (scanned or modelled reclaimed elements) and the demand side (design lines). Collect the objects with LinearSet, which expands them by Quantity and outputs effective lengths, areas and lines for FeatureVector and Match. LineScore measures how well a line represents the object.

Notes

  • Error: "Buffer must be > 0" when LengthBuffer ≤ 0, plus the geometry errors listed under Object.
  • For a straight line, or any curve lying in a plane, Height is 0 (and Width is 0 for a straight line), so the estimated area is 0. Supply Area explicitly in that case.
  • Quantity 0 makes the object contribute no rows to LinearSet; a negative Quantity, or NumSamples < 1 for a curve or Brep, is an error.
  • An estimated area (no Area given) is recomputed from the new box when the axes are changed with OverridePCA; a given Area is kept.

Object

A design object

Nickname: Obj

Object analyzes one piece of geometry and wraps the result in a design object: a local coordinate frame, the object's extents in that frame, sampled points and convex hulls. All other DCT object types (LinearObject, PlanarObject, BoxObject, SphericalObject) run exactly the same analysis and add their own parameters on top, so this note also describes them.

Input geometry. Curves, Breps, meshes and point clouds are analyzed directly. Surfaces and extrusions are converted to Breps, and SubDs to a mesh (Mesh.CreateFromSubD at density 1), before analysis. The input geometry is never modified; the converted geometry is what the object stores and what the Geometry output returns.

Sampling (NumSamples). PCA runs on a set of sample points, not on the exact geometry:

  • Curve: NumSamples segments of equal arc length (Curve.DivideByCount). An open curve gives NumSamples + 1 points including both ends; a closed curve gives NumSamples points.
  • Brep: the Brep's wireframe curves (Brep.GetWireframe at density 1) are divided with a share of NumSamples proportional to each curve's length (at least 2 segments per curve, interior division points only), and all Brep vertices are added. The total is therefore approximately NumSamples.
  • Mesh: all mesh vertices. NumSamples is ignored.
  • Point cloud: all points. NumSamples is ignored.

The points are not weighted, so regions with denser sampling (for example finely meshed areas) pull the axes towards them.

Local frame (PCA). The covariance matrix of the sample points is computed and its eigenvectors, sorted by decreasing eigenvalue (variance), give the principal axes: PCA1 is the direction of greatest spread, PCA2 the greatest spread perpendicular to it, PCA3 the least. Eigenvectors have no inherent sign, so DCT fixes one: PCA1 is flipped if needed so its world X component is non-negative (if that component is zero, Y, then Z decide); PCA2 so its world Y component is non-negative (ties: Z, then X); and PCA3 = PCA1 × PCA2, so the frame is always right-handed. When two variances are equal (a straight line, a square plate, a sphere) the axes within that plane are mathematically undefined and their direction is arbitrary.

Centroid, box and dimensions. The centroid is the area centroid for a closed planar curve and the mean of the sample points otherwise. A bounding box of the full geometry (not of the samples) is then computed in the frame PCA1/PCA2/PCA3. Length, Width and Height are the extents of that box along PCA1, PCA2 and PCA3, in document units. The local plane (X = PCA1, Y = PCA2) is placed at the center of this box, which in general differs from the centroid. A 2D convex hull of the sample points projected onto the local plane is stored; the 3D convex hull of the samples is built only when first requested. Use ObjectProperties to read all of these values.

Typed objects: Quantity, buffers, ID. The typed constructors add:

  • Quantity: how many identical copies the object represents. The Set components (LinearSet, PlanarSet, BoxSet, SphereSet) repeat the object that many times in their outputs. It does not change the analysis.
  • Buffers (LengthBuffer, WidthBuffer, HeightBuffer, RadiusBuffer): factors that scale the measured dimension into an effective dimension, for example EffectiveLength = LengthBuffer × Length. They affect the effective geometry and the Set outputs, not the measured Length/Width/Height. Values must be greater than 0.
  • ID: a text label carried with the object and returned by the Set components and ObjectProperties.

Object itself has no quantity or buffers. Use it for objects that will be inspected, scored (LineScore, PlaneScore), reoriented (OverridePCA, RotatePCA, AlignToPlane) or outlined (PlanarOutline, PlanarHull) rather than collected into a Set.

Notes

  • Errors: "Unsupported geometry type ... Supported: curves, Breps/surfaces/extrusions, meshes, SubDs and point clouds." and "Could not convert the ... for analysis".
  • With Grasshopper's Parallel Computing option enabled on the component, items are analyzed in parallel.
  • For a planar curve or a flat point set, Height is 0 and the 3D hull is an empty mesh.
  • NumSamples is a target, not an exact count; more samples give more stable axes for irregular geometry at a higher cost.

PlanarObject

A planar object

Nickname: PlaneObj

PlanarObject abstracts a piece of geometry as a rectangular plate with a thickness. It runs the same sampling and PCA analysis as Object (see that note for how NumSamples, the PCA frame and Length/Width/Height are defined) and then stores Quantity, the two buffers, Thickness and ID.

Effective plane. EffectivePlane is a planar surface in the local plane (X = PCA1, Y = PCA2), centered on the center of the PCA-aligned bounding box, with side lengths

\[L_\text{eff} = \text{LengthBuffer} \times \text{Length}, \qquad W_\text{eff} = \text{WidthBuffer} \times \text{Width}\]

Because the surface passes through the box center, it lies at mid-thickness of the object.

Thickness. If Thickness is greater than 0 that value is used. Otherwise the thickness is the object's Height, its extent along PCA3. No buffer is applied to the thickness.

Workflow. Use it for panels, boards, sheets and other flat elements. Collect supply and demand objects with PlanarSet, which expands them by Quantity and outputs effective lengths, widths and thicknesses for FeatureVector. PlaneScore measures how well a plane represents the object, and PlanarOutline gives its outline for shape descriptors.

Notes

  • Error: "Buffer must be > 0" when LengthBuffer or WidthBuffer ≤ 0, plus the geometry errors listed under Object.
  • For a curve or point set lying in a plane, Height is 0, so the automatic thickness is 0. Supply Thickness explicitly in that case.
  • Quantity 0 makes the object contribute no rows to PlanarSet; a negative Quantity, or NumSamples < 1 for a curve or Brep, is an error.
  • The output PlanarObject carries all of the above and can also be read with ObjectProperties, which reports the unbuffered dimensions.

SphericalObject

A spherical object

Nickname: SphereObj

SphericalObject abstracts a piece of geometry as a sphere. It runs the same sampling and PCA analysis as Object (see that note for how NumSamples and the PCA frame are defined) and then stores Quantity, RadiusBuffer and ID.

Effective sphere. The center is the center of the object's PCA-aligned bounding box. The radius is the largest distance from that center to any of the sample points, so the sphere encloses all samples (not necessarily every point of the exact geometry between samples). The effective radius is

\[r_\text{eff} = \text{RadiusBuffer} \times r\]

and EffectiveSphere is the sphere with that center and radius. Both are computed once, when the object is constructed.

Workflow. Use it for compact, roughly isotropic elements such as rubble, stones or nodes, where orientation does not matter. Collect supply and demand objects with SphereSet, which expands them by Quantity and outputs effective radii for FeatureVector. SphereScore measures how well the sphere represents the object.

Notes

  • Error: "Buffer must be > 0" when RadiusBuffer ≤ 0, plus the geometry errors listed under Object.
  • The radius depends on the sampling: for meshes and point clouds all vertices or points are used; for curves and Breps more NumSamples gives a tighter estimate.
  • Quantity 0 makes the object contribute no rows to SphereSet; a negative Quantity, or NumSamples < 1 for a curve or Brep, is an error.
  • When the axes are changed with OverridePCA, the sphere is recomputed about the new box center.

ObjectProperties

Properties of a design object

Nickname: ObjProps

ObjectProperties unpacks the analysis stored in a design object. It accepts any DCT object: the output of Object, LinearObject, PlanarObject, BoxObject or SphericalObject, including objects moved or reoriented by OverridePCA, RotatePCA, AlignToPlane or AlignToObject. Nothing is recomputed except the 3D hull, which is built on first request.

What the outputs mean (see the Object note for how they are derived):

  • PCA1, PCA2, PCA3: the unit axes of the right-handed local frame.
  • Length, Width, Height: extents of the geometry along PCA1, PCA2, PCA3. These are the measured values; buffers of typed objects are not applied, so they can differ from the effective dimensions reported by the Set components.
  • BoundingBox: the PCA-aligned bounding box of the geometry, as an oriented box in world coordinates.
  • LocalPlane: the plane with X = PCA1, Y = PCA2, placed at the center of BoundingBox.
  • Centroid: the area centroid for a closed planar curve, otherwise the mean of the sample points. It is generally not the same point as the origin of LocalPlane.
  • PlanarHull: the convex hull of the sample points projected onto LocalPlane.
  • VolumeHull: the 3D convex hull of the sample points, as a mesh.
  • SampledPoints: the points the PCA was computed from (curve divisions, Brep wireframe samples and vertices, mesh vertices or point-cloud points).
  • Geometry: the stored geometry (after any conversion of surfaces, extrusions or SubDs).

Workflow. Use it to check that the axes and dimensions match expectations before building feature vectors, or to take individual values (for example Height or Centroid) into custom calculations and FeatureVector.

Notes

  • VolumeHull is computed only when it is connected or the component preview is on. It is an empty mesh when the samples are collinear or coplanar (for example a planar curve).
  • IDs returns the single ID of the input object.

OverridePCA

Override the calculated principal components with a plane whose X,Y components = PCA1, PCA2

Nickname: OverridePCA

OverridePCA replaces the computed principal axes of a design object with a user-defined frame. Use it when PCA picks an orientation that is not the meaningful one, for example when the grain direction of a board is known, when a square or circular object has ambiguous axes, or when demand and supply should be measured in a common orientation.

How it works. The component works on a copy of the input object; the upstream object is not changed. The PrincipalPlane input defines the new frame: its X axis becomes PCA1, its Y axis PCA2 and its Z axis PCA3. The plane's origin is ignored; the frame is anchored at the center of the object's current bounding box. The plane's axes are used as given, so the sign rule of the automatic analysis (described under Object) does not apply.

With the new frame, the component recomputes the bounding box of the geometry, so Length, Width and Height become the extents along the new axes; moves the local plane to the center of the new box; and rebuilds the planar convex hull of the samples in the new local plane. The sample points, centroid and 3D hull are unchanged.

The output keeps the input's object type, Quantity, buffers and ID. Quantities derived from the box when read (the effective line, plane or box, and the automatic Thickness of a PlanarObject) follow the new axes.

Workflow. Place it between an object constructor (Object, LinearObject, PlanarObject, BoxObject, SphericalObject) and the matching Set component, or before ObjectProperties or PlanarOutline. To rotate about an existing axis instead, see RotatePCA.

Notes

  • Values derived from the box are updated too: the estimated Area of a LinearObject (a given Area is kept) and the sphere and radius of a SphericalObject, recomputed about the new box center. The planar hull lies in the new local plane. Before v0.5.1 these kept their original values.
  • No output is produced if either input is missing.
